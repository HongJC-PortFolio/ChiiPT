# 기능 명세서 및 구현 설계서

- 기능 정의: 어떤 조건에서 어떤 동작을 수행할 것인가?
- 구현 설계: 어떤 기술과 방식으로 구현할 것인가?
- 개발 범위: 해커톤에서 어디까지 구현하고, 무엇을 추후 확장할 것인가?

---

- **자세 불균형 감지**
    
    
    | 항목 | 구현 명세 |
    | --- | --- |
    | 기능명 | 자세 불균형 감지 및 캐릭터 반응 |
    | 기능 동작 |   1. 사용자가 Windows 앱 설치 후 실행한다. 
      2. 최초 실행 시 웹캠 사용 권한을 확인하고 기준 자세를 등록한다. 
      3. 사용자가 바른 자세를 유지하는 동안 기준값을 측정해 로컬에 저장한다. 
      4. 이후 실행부터 저장된 기준값을 불러와 자세를 감지한다. 
      5. 왼쪽 또는 오른쪽으로 기울어지면 캐릭터가 해당 방향으로 구른다. 
      6. 불균형이 지속되면 캐릭터가 맨 앞 화면에서 계속 움직이며 시야를 방해한다.
      7. 바른 자세로 돌아오면 움직임을 멈추고 원래 위치로 복귀한다. 
      8. 앱 종료 또는 자세 감지 비활성화 시 카메라 사용을 중단한다. |
    | 구현 방식 |   • 초기 보정: MediaPipe로 어깨·얼굴 등의 랜드마크를 추출하여 기준 자세를 저장한다. 
      • 실시간 감지: 웹캠 영상에서 좌우 기울기를 계산하고 기준값과 비교한다
      • 상태 판단: 정상·왼쪽 기울어짐·오른쪽 기울어짐·인식 불가 상태로 분류한다.
      • 캐릭터 연동: 상태와 기울기 정도를 애니메이션 시스템에 전달한다.
      • 화면 표시: Electron의 투명 오버레이 창으로 캐릭터를 다른 프로그램 위에 표시한다. |
    | 사용 기술 |   • Electron + TypeScript: Windows 앱 및 오버레이. 
      • MediaPipe Tasks Vision / Pose Landmarker: 신체 랜드마크 추출. 
      • Pixijs: 캐릭터 렌더링 및 애니메이션. 
      • Electron IPC: 자세 감지 결과와 캐릭터 제어 간 통신.
      • electron-store 또는 JSON 기반 로컬 저장: 기준 자세와 사용자 설정 저장. 
      • electron-builder: Windows 설치 파일 생성. |
    | 기술적 고려사항 |   • 인식 정확도: 카메라 각도 및 상체 가림에 따른 오차. 
      • 기준 자세: 사용자별 초기 보정 및 재설정. 
      • 오탐 방지: 순간적인 움직임을 자세 불균형으로 판단하지 않도록 지속시간과 허용 범위 설정. 
      • 성능: 카메라 추론과 캐릭터 렌더링 분리. 
      • 오버레이: 항상 위 표시와 마우스 클릭 통과 처리. 
      • 개인정보: 영상 저장·외부 전송 없이 로컬 처리. 
      • 예외 상황: 카메라 연결 해제, 권한 거부, 사용자 이탈 시 안전하게 감지 중단. |
    | 필수 구현 범위 |   • 최초 기준 자세 등록 및 저장
      • 실시간 좌우 기울기 감지 → 방향별 캐릭터 굴러가기 → 자세 복귀 시 원위치
      • 항상 위 오버레이
      • 감지 ON/OFF, 카메라 오류 처리 |
    | 추가 구현 범위 |   • 고개를 화면 쪽으로 내미는 동작 감지 → 전방 자세에 따른 캐릭터 반응
      • 기울기 정도에 따른 애니메이션 속도 변화
      • 사용자별 민감도 조정 |
- **온오프기능 (기본 전제)**
    
    
    | 항목 | 상세 내용 |
    | --- | --- |
    | 기능명 | 캐릭터 수면·기상 상호작용을 통한 ON/OFF 제어 |
    | 기능 목적 | 별도의 ON/OFF 버튼 대신 캐릭터를 재우거나 깨우는 상호작용을 통해 웹캠 기반 인식 기능을 제어하고, 캐릭터의 생동감과 사용자 몰입도를 높인다. |
    | 기능 동작 |   1. 프로그램 실행 시 기본적으로 Awake 상태로 시작하며, 카메라 권한이 허용되어 있다면 자세 및 손동작 인식을 활성화한다.
      2.  Awake 상태에서 캐릭터를 마우스로 약 2초간 길게 누르면 하품하고 웅크려 잠드는 모션이 실행된다.
      3. Sleep 상태로 전환되면 웹캠 및 MediaPipe 인식을 중단하고 수면 대기 모션을 유지한다.
      4. 잠든 캐릭터를 마우스로 더블클릭하면 비몽사몽 깨어나는 모션이 실행된다.
      5.  Awake 상태로 전환되면 웹캠 및 MediaPipe 인식을 재개하고 자세 교정·쓰다듬기 기능을 활성화한다. |
    | 구현 방식 |   • Electron : 캐릭터 영역의 마우스 입력 
      • PixiJS : 수면·기상 전용 애니메이션을 구현한다.
      • TypeScript : 
          ◦ 캐릭터 상태를 `Awake`, `FallingAsleep`, `Sleep`, `WakingUp`으로 관리 
          ◦ 상태 전환에 따라 공통 웹캠 및 MediaPipe 인식 모듈의 실행 여부를 제어 |
    | 사용 기술 |   • Electron + TypeScript
      • PixiJS
      • MediaPipe Tasks Vision
      • Electron IPC, electron-store |
    | 기술적 고려사항 |   • 캐릭터 클릭 영역에서만 마우스 입력을 허용해 다른 프로그램의 조작을 방해하지 않도록 한다.
      • 길게 누르기와 더블클릭을 구분해 의도하지 않은 상태 전환을 방지한다.
      • Sleep 상태에서는 카메라 스트림과 추론 작업을 실제로 중단한다.
      • 기상 과정에서 카메라 권한 거부·연결 실패 시 오류 상태를 표시한다.
      • 상태 전환 중 중복 입력과 기존 자세 교정·쓰다듬기 애니메이션의 충돌을 방지한다.
      • 캐릭터를 조작할 수 없는 경우에도 시스템 트레이에서 인식 기능을 제어할 수 있도록 한다. |
    | 필수 구현 범위 |   • 마우스 길게 누르기로 재우기, 더블클릭으로 깨우기
      • 수면·기상 전용 모션, Awake/Sleep 상태 관리
      • 웹캠 및 MediaPipe 활성화 
      • 동기화 시스템 트레이 대체 제어 |
    | 추가 구현 범위 |   • 하품·눈 비비기·기지개 등 세부 모션
      • 수면 중 호흡 및 Zzz 효과, 전환 효과음 
      • 사용자 지정 조작 방식
      • 마지막 수면 상태 저장 |
- 힐링
    
    
    | 항목 | 구현 명세 |
    | --- | --- |
    | 기능명 | 스트레스 완화를 위한 캐릭터 상호작용 |
    | 기능 동작 | 1. 사용자가 Windows 앱을 실행하고 웹캠을 활성화한다.
    2. MediaPipe가 사용자의 손 위치와 움직임을 실시간으로 인식한다.
    3. 사용자가 화면 속 캐릭터의 머리 위치에 손을 가져간다.
    4. 손가락이 캐릭터의 머리 영역에서 쓰다듬는 움직임을 보이면 상호작용을 감지한다.
    5. 캐릭터가 눈을 감거나 미소 짓고, 몸을 흔드는 등 긍정적인 반응을 보인다.
    6. 사용자가 손을 떼거나 움직임을 멈추면 캐릭터가 자연스럽게 기본 상태로 복귀한다.
    8. 앱 종료 또는 손동작 감지 비활성화 시 해당 인식을 중단한다. |
    | 구현 방식 | • 손동작 인식: MediaPipe로 손가락과 손바닥의 랜드마크를 추출한다.
    • 좌표 변환: 웹캠에서 인식한 손 위치를 캐릭터가 표시된 화면 좌표에 대응시킨다.
    • 상호작용 판단: 손가락 위치, 캐릭터 머리 영역과의 겹침, 손의 이동 방향 및 지속시간을 이용해 쓰다듬기를 판단한다.
    • 상태 판단: 대기·손 접근·쓰다듬기·상호작용 종료 상태로 분류한다.
    • 캐릭터 연동: 인식된 상호작용 상태를 애니메이션 시스템에 전달해 표정과 움직임을 변경한다.
    • 화면 표시: Electron의 투명 오버레이 창에서 캐릭터의 반응을 실시간으로 출력한다. |
    | 사용 기술 | • Electron + TypeScript: Windows 앱 및 투명 오버레이.
    • MediaPipe Tasks Vision / Hand Landmarker: 손가락·손바닥 랜드마크 추출.
    • PixiJS: 캐릭터 렌더링, 표정 및 움직임 애니메이션.
    • Electron IPC: 필요한 경우 앱 프로세스 간 상태 및 설정 전달.
    • electron-store 또는 JSON 기반 로컬 저장: 손동작 인식 설정과 사용자 환경설정 저장.
    • electron-builder: Windows 설치 파일 생성. |
    | 기술적 고려사항 | • 손동작 인식: 조명, 손 가림, 카메라 위치에 따른 인식 오차.
    • 좌표 일치: 웹캠 좌표와 화면 속 캐릭터 위치 간 정합성 및 좌우 반전 처리.
    • 오탐 방지: 손이 단순히 지나가는 행동을 쓰다듬기로 판단하지 않도록 이동 패턴과 지속시간 설정.
    • 애니메이션: 반복 상호작용 시 표정과 움직임이 부자연스럽게 끊기지 않도록 처리.
    • 기능 충돌: 자세 불균형 반응과 쓰다듬기 반응이 동시에 발생할 때 모션 우선순위 설정.
    • 성능: 손·자세 인식 시 웹캠 영상 공유 및 추론 부하 관리.
    • 오버레이: 클릭 통과 상태에서도 손동작 상호작용이 가능하도록 구현.
    • 개인정보: 웹캠 영상 저장·외부 전송 없이 로컬 처리.
    • 예외 상황: 손 인식 실패, 카메라 연결 해제, 권한 거부 시 기본 상태 유지. |
    | 필수 구현 범위 | • 웹캠 기반 실시간 손 위치 및 움직임 인식.
    • 캐릭터 머리 영역에 대한 쓰다듬기 동작 판별.
    • 쓰다듬기 감지 → 캐릭터 표정 및 몸체 반응 → 상호작용 종료 시 기본 상태 복귀.
    • 자세 불균형 감지 기능과 동일한 캐릭터 및 웹캠 공유.
    • 손동작 감지 ON/OFF 및 카메라 오류 처리. |
    | 추가 구현 범위 |   • 쓰다듬는 방향·속도·횟수에 따른 다양한 반응.
      • 볼 잡기 및 늘리기 등 추가 손동작 상호작용.
      • 상호작용 지속시간에 따른 표정과 애니메이션 변화.
      • 캐릭터의 감정 표현을 위한 효과음 및 시각 효과.
      • 사용자별 손동작 인식 민감도 조정.
      • 쓰다듬는 행동이 지속 시 → 추가적인 표정과 움직임으로 반응. |
